## Three AI outputs that looked right and were not trustworthy at first

1. **"200 concurrent tasks" that never overlapped.** The first concurrency tests used `WorkerThreadPool` and passed
   5 of 5 runs. On the 1-CPU machine the pool has one worker, so `max_concurrent` was 1: the tests checked nothing
   about concurrency. Found by measuring the overlap; fixed with one `Thread` per task and an assertion
   `max_concurrent >= 2` (evidence: `03-concurrency-notes.md`, finding 1).
2. **An assertion that follows the bug (TC-06).** The test checked that every exported key is in
   `RunExportService.EXPORT_FIELDS`, the constant of the code under test. Mutant F1 (adds `expires_at` to that
   constant) survived the first mutation run (25 of 27 killed). Found by the mutation run; fixed by TC-20, which names the fields
   that must not leave (evidence: `12` against `13`).
3. *(extra)* **A confident conclusion from an empty experiment.** The first spike reported "0 torn reads in
   10,100 reads" and the plan review used it to weaken a risk. It ran on the same non-overlapping pool; with real
   threads the torn reads appear (410 unreadable files in 20 runs). Plan review R4 now carries the correction.
